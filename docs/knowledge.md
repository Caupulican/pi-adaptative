# Accepted knowledge in ICM

ICM keeps accepted knowledge in `memory/knowledge.sqlite` under the agent directory, separately from conversation history. Records cover the owner's profile, behavioral preferences, procedures, taste in how code and other work products are written, workstream decisions, related people and organizations, and dated journal facts. Each record has a scope, evidence citations, validity dates and a revision history.

The main session receives a bounded current view through the normal memory request planner, including in continuous chat. Explicit, applicable and recent facts take priority. Future and expired records are excluded, and the view reports omissions. Knowledge changes invalidate a pending request plan; the next request reads the committed revision. The chat's cached summary prefix stays stable. Derived knowledge projections exist only on the current request; they never enter durable conversation history or chat summaries.

The `knowledge` tool reads and changes this collection on demand:

- `search` accepts up to eight terms, an optional category and an `after` cursor. Omitting the query browses the category.
- `read` opens an exact record ID and pages its evidence citations.
- `history` pages earlier revisions of an exact record ID. Expired and historical records are evidence, not current instructions.
- `evidence` pages original owner inputs in 4,000-character portions. Its cursor names the exact source record and offset. Older truncated sources are identified as incomplete.
- `change` accepts a `remember` or `forget` command with original owner source IDs and quotes. A targeted correction or forgetting also names the current record ID and expected revision. The host checks the evidence, semantic meaning and canonical identity before writing. Held proposals are not saved.

Audience and project identity are supplied by the host. New facts can apply globally or to the current project. The root tool cannot be delegated to workers or read another audience's records. A worker task receives exactly the records the root grants it by ID and revision: `delegate` workers through their request view and `memory_read`, and `pi_collaboration` tasks through one bounded block in the task prompt, handed from the parent session's memory right before the prompt and never written to job files. A version already corrected or forgotten when the task is granted, or when the task is about to be prompted, is not delivered. A grant is not a confidentiality boundary against the worker it is granted to: that worker's own reports may quote the values (see [Delegated workers](../packages/coding-agent/docs/memory.md#delegated-workers)). Disabling memory retrieval disables reads; excluding memory from the prompt removes the automatic view without disabling explicit reads. Explicit requested changes remain possible while retrieval is off.

Current owner instructions and corrections take precedence. Stored preferences do not grant permissions. Forgetting removes the accepted value, its revision history and its subject/key names; only the identity digest and an evidence barrier remain, so no later judgment can read or send a forgotten name. Owner evidence older than any request to forget never teaches knowledge again, under any wording. A newer explicit instruction can relearn it; old remember or forget requests cannot overwrite newer evidence. Through the `knowledge` tool, forgetting or correcting an existing fact must cite the owner's own statement from the turn the tool call answers. Setting a validity that ends a current fact is forgetting it and needs the same explicit request. This does not delete the original conversation, including dated tool-result echoes. Those echoes are historical evidence, not a current knowledge view.

Inferred changes require independent original sources and the existing learning policy. Disabling Auto Learn still permits explicit owner requests to remember, correct or forget. A semantic judge must establish the meaning of a proposed change; an uncertain verdict leaves it held. System One judges when it is bound. Otherwise the collection model (`autoLearn.model`, the session model by default) judges each change through one isolated structured submission, spending under the same per-change and per-session knowledge limits as automatic collection. Its confidence is self-reported, not a calibrated probability, so under it an inferred pattern is held, background collection never forgets (ask for the forgetting directly), and a proposal that matches a live fact without naming it is held until it names that record's exact ID and expected revision. A forgotten identity can still be relearned. Without a usable model, or with one that has no declared price, no judgment runs and the change is held or refused. Secret-bearing sources and values are refused before admission. Originals of up to 16,000 characters are judged whole, within the semantic engine's state capacity. Longer originals are judged window by window: 8,000-character cores with up to 2,000 characters of surrounding context on each side. No window may contradict the change or leave it unresolved, and at least one must support it. An identity scan covers at most 2,000 canonical identities. Exceeding a bound leaves the proposal held.

Earlier knowledge databases migrate on open. Schema 5 erases the names of previously forgotten records and seeds the forget barrier with the latest barrier those records kept. Schema 6 adds a per-source retry count. A deleted value is never reconstructed from conversation history. A database migrated to a newer schema cannot be opened by an earlier build.

Automatic collection (`autoLearn.enabled`, on by default) runs in persisted ICM root sessions whenever a priced collection model and a judge are available. After owner input and an idle delay, an isolated extraction reads complete original owner inputs and proposes bounded changes. Those proposals pass through the same admission as the `knowledge` tool. Its spending is limited per original source and per session; an exhausted allowance or a per-source limit of zero holds new sources before any request until the limit changes. A verdict already paid for is kept (content-free) and reused for the same question, state and judge. A held source is judged again only when knowledge, the configuration or the settled spending it waits on changes, never merely because the owner wrote again; a source that returns from a paying hold four times waits for a configuration change, whatever the model costs. Owner input, new owner evidence and a settings change never interrupt a collection request already sent: it finishes, its result is kept, and the pass then stops before its next request; the next pass reuses that result instead of buying it again. A request that fails with a received, measured response releases its work for a later attempt; a request interrupted in flight (by the pass deadline or by shutdown) is never replayed automatically, because the provider may have produced a result nobody received. Before any judgment is paid for, the host checks every citation against the complete original: a quote that overlaps text the owner pasted into the interactive editor (recorded with the message as pasted ranges, whatever its delimiters), a quotation (ASCII, curly, low-9, guillemet or CJK quotes), a fenced or indented code block, a blockquote or a quote element is rejected as shown, not stated; it must carry at least four letters or digits of the owner's own words; a fact term found in the cited sources only inside shown text rejects the change (a pasted "I live in Paris" never yields Paris); and a quote whose source states a fact term must itself state one. Inline code inside an owner sentence still counts as the owner's words. A part of a paste the owner edited counts as their own words. Unmarked text without recorded paste provenance (sent through RPC, print mode or an extension, or typed rather than pasted), unmarked attribution ("my friend says ...") and a fact sharing no words with its source are left to the semantic judgment. In-memory-only and child sessions never collect.

`/memory knowledge` and `context_audit` report whether collection is active, which judge it uses, its spending against the session limit and its last pass, or the reason it starts no requests: disabled, invalid or unreadable settings, no model, an unpriced model, no judge, an exhausted allowance, unsettled spending, an unpersisted or child session, or ICM memory not active.

## Owner controls

The owner views and edits accepted knowledge directly with `/knowledge` in an interactive ICM root session. No model takes part:

- `/knowledge list [<kind>|global|project] [<after-id>]` lists current records ten at a time. Each line shows the record's ID prefix, category, reach, revision, basis, validity state, last evidence date and value. A full page ends with the command for the next page.
- `/knowledge show <id> [<citation-offset>]` shows one record: subject and key, value, first and last evidence dates, validity interval and its citations four at a time (owner message or owner command, time, session, source and quote).
- `/knowledge history <id> [<before-revision>]` pages retained revisions five at a time.
- `/knowledge correct <id> <new value>` replaces the record's value with the text after the ID, taken verbatim apart from surrounding whitespace. Identity, category, scope, validity interval and first evidence date are kept, and the previous value stays in its history.
- `/knowledge forget <id>` forgets the record exactly like a forget through the tool: the value, its history and its names are removed, and only the identity digest stays as an evidence barrier.
- `/taste [<after-id>]` prints the accepted `taste` records as Markdown, grouped by reach (this project, global) and subject. Each fact shows `stated` or `inferred`, the number of distinct original owner sources across its revisions, the last evidence date and the short ID. `/taste export [path]` writes the same view to `.pi/taste.md` (or the path given; a relative path stays inside the working directory) under a first line that marks it as generated. It changes nothing; edit through `/knowledge correct` and `/knowledge forget`. `/taste proposals` lists candidate facts that wait for the owner; `/taste accept <id>` states one after the owner confirms its text, and `/taste reject <id>` drops it for good. A proposal is not knowledge until accepted (see `packages/coding-agent/docs/memory.md`).

An ID is the full record ID or a unique prefix of at least eight characters within the owner's current scope. Output is bounded per line and known secret patterns are redacted.

A correction or forget first asks for confirmation on the owner's screen and changes nothing until the owner accepts. Without a bound owner UI it is refused. The change then passes through the same admission and store as the tool: the revision read before the confirmation must still be current, forgotten sources and newer-evidence fences apply, and a retry of the same command against the same revision returns its recorded outcome instead of applying twice. The command needs no semantic judgment and spends nothing, with or without System One. Its evidence is the command itself: the citation records the typed command text, the session and a time after the record's last evidence, under an `owner-command:` source ID. This evidence is not added to the original owner-evidence ledger, so collection and model-proposed changes still cite only original owner messages; pasted text, worker reports and summaries never become owner knowledge through a command. A command or value containing a credential is refused.
