# Interactive Workbench

Human interactive sessions use a full-screen Workbench with the selected terminal theme, including Matrix. Unattended sessions retain their transcript layout.

Rows, top to bottom: a title strip (the plan or goal naming the work, else the session name or folder name; blank when it would only repeat the application's own name), the work area (Work plan and Team on the left, Execution on the right; it takes no rows and has no divider until there is something to show: a command or file effect, or a plan), its divider (a drag handle, `↕`, while expanded; while collapsed, a summary of what the work area holds — its blocks, and Execution only when it has evidence — or a bare rule when it holds nothing), the conversation zone (the **Decision graph** on the left and the conversation on the right, or the conversation alone when the graph is hidden or the width cannot hold both), the **live row** (the one run-state indicator: `● subject (elapsed)`; the subject is the single running tool or worker when there is exactly one, otherwise the live runtime label such as *Thinking* or *Working*, with the plan step, concurrency counts, the message queue and the newest event on the right; the row is reserved and blank while idle so geometry never jumps), the **operator POV bar** (see below) on the status band's surface, the status band (transient notices, extension widgets and session status), the editor inside its own top and bottom rules (its placeholder carries the hints: `Ask anything · / commands · @ files · ! bash · escape interrupt · alt+enter follow-up · alt+o work area · ? shortcuts`; `?` on an empty editor, or `/hotkeys`, opens every shortcut in a floating window), extension widgets below it, and the status line: the branch and its pull request (`PR #123`, from `gh`, coloured by whether it is open, merged or closed) at the left, the model and its thinking level (a meter that fills and warms with the level; `Shift+Tab` steps it) at the right. The status band, the editor and the status line are one panel on the surface tone, without gaps. Panes that sit side by side are separated by a one-column dim rule; where a rule meets the divider the junction (`┴`, `┬`, `┼`) is composed into the divider. Zones separate by surface tone (`workbenchSurface`, optional in custom themes and defaulting to the custom-message background), spacing and those rules; nothing is boxed.

The default layout stays stacked: work area above, conversation below. `Alt+P` puts Conversation on the left and Execution on the right of the same rows (drag the gutter to resize; the conversation header's **Stacked** chip or `Alt+P` restores the default). **Hide** still removes the work plan so code takes the whole right column. The inspector on the left (30% of the width by default: a **Work plan** block with completed/total steps and a **Team** block with active agents, each with a quiet placeholder when empty) and **Execution** on the right (file effects and command outcomes, with a placeholder until the first evidence) remain the work-area contents. By default it takes about a third of the rows left after the title strip, the live row and the status band (35%, so the conversation keeps the larger share of a tall terminal); the conversation always keeps at least six rows, and only the operator changes the geometry. The first `Alt+=` / `Alt+-` turns the automatic split into an explicit row count that persists. `Alt+O` (or, with the mouse captured, a click on the divider) collapses it to the divider row, which then summarizes the blocks, and expands it again; dragging that divider resizes the work area (a drag onto the title strip collapses it). `Alt+=` and `Alt+-` add or remove a row; `Alt+I` or **Hide** on the Work plan title hides the inspector so Execution takes the full width, and **Show plan** on the Execution title shows it again; `Alt+X` or **Maximize** on the Execution title maximizes Execution to every row the conversation minimum leaves (the inspector hidden meanwhile) and **Restore** returns the previous rows. Dragging the gap between the panes changes the inspector's width (20%–45%). Rows, collapsed state, inspector visibility, inspector width, layout (`stacked` or `columns`), conversation column width, the maximized flag, the preview retention and the Decision graph's visibility, width and view persist in settings (`workbench.rows`, `workbench.collapsed`, `workbench.inspector`, `workbench.inspectorFraction`, `workbench.layout`, `workbench.conversationFraction`, `workbench.executionMaximized`, `workbench.previews`, `workbench.graph`, `workbench.graphFraction`, `workbench.graphView`) and are restored at start; each pane title carries one chip (**Hide** on the Work plan, **Maximize** / **Restore** or **Show plan** on Execution), every other action lives on a key (the hint row names the few that matter every turn, `/hotkeys` lists the rest). Tool output never moves the conversation boundary: previews scroll inside their surface. Terminals narrower than 80 columns stack Execution above the inspector, and very short terminals show both in one scrolling surface or, below two rows, only the divider. Status and input stay anchored below the conversation. Extremely small terminals omit gutters to preserve native input and its cursor. A question dialog sits in the editor slot and receives a row budget from the host, so a question with many options scrolls inside its lane (the active option, the title and the help row stay visible) instead of taking over the screen.

A reply carries a byline, one dim row above it, only when it was not written by the session's own model (that one is on the status line): `routed · <model name> · <route>` on the warning tone when a routed model wrote it, with the route in the POV bar's ROUTE words (`cheap via model-router/System One`). It appears on the first routed reply after each of your messages and again only when the replying model changes, so a tool-heavy turn does not repeat it; a narrow pane shortens it from the end and never wraps it. A routed reply's route is recorded in the session (`reply_route`), so a resumed conversation shows the same bylines.

Evidence stays on screen until it is replaced: completion does not fold it, and a new cycle keeps the previous cycle's previews and counters until its own first tool result, file effect or Jev evaluation arrives. Each entry has two parts that cannot be mistaken for each other. The CALL is a full-width bar on a raised surface (red when failed): a status mark (`✓`, `✗`), the tool in bold and what it ran (the command, or the file for an edit or write); a producer is named at its right only when it is not the session's own model (a routed turn or a worker, by display name), because the status line already names the session's model. The OUTPUT is its own bordered box beneath it, titled in its top border (`output · 3 lines`, `diff +2 −1`, `error`, `reasons`), on a surface distinct from the bar and the pane, in the main text color, with its source lines numbered (a diff carries its own numbers; a long line wraps under its number). In a shell's output, any word that names something that exists on disk is shown as a path in the link tone: relative to the session's folder as `./path`, a folder with a trailing `/`, a path outside the folder absolute, an attached `:line` kept; bare names are resolved against the folder and against any existing folder the command named (`ls packages` shows `./packages/ai/`). A word is a path because it exists, never because of how it looks, so ordinary text stays text. A call with no output is just its bar. The pane manages its entries so a long run stays readable: the newest entry and any failed one are open, every older entry folds to its call bar (a `▸` chevron, with the output's summary at the right: `30 lines`, `+2 −1`, `error · 4 lines`), and an output past twelve lines is trimmed to twelve with a `▾ N more lines · click to show all` row inside its box. A click on a bar folds or unfolds that entry, a click on the show-all row opens the whole output, and the operator's choice for an entry holds until the entry leaves the pane. Entries are separated by a blank row. Observed workspace changes are one entry (`file changes`, `N files`) whose output lists the files as bullets above the current diff. The pane's title carries the counts once, in plain words (`1 done · 2 file changes`, `1 running`, `3 pending`, `1 in background`); the body adds a `!` row only when something went wrong (failed, unknown effects, unclassified, postprocessing faults, conflicting receipts, kept error results). A routine System One judgment is not Execution evidence (the Decision graph shows the count, the last verdict and the kinds); only a FAILED evaluation keeps its own entry, on the error tone, and replaces itself in place when a later verdict is noted. Failure counts remain visible until session replacement. A finished plan folds to one `Work complete` row and an idle team to one `Team idle · N sessions retained` row without deleting tasks, worker sessions or durable evidence. A retired worker (`delegate retire`) is no longer a retained session: it leaves the Team row while its binding and transcript stay reachable through `delegate list` / `transcript`. Long plans show up to six prioritized rows (blocked and failed first, then active, then pending) with the hidden count; use the existing work/team inspector for the complete state. Edit previews carry their added/removed line counts.

The **Team** block is a hierarchy read from live state on every frame. **Decider** comes first: `◆ System One` with what it is judging and a running clock while an evaluation is in flight, or `◇` with its last verdict and label, or `ready` / `off`; beneath it who holds control (`decides next` while CONTROL is S1, `waiting for you` while a question is open, `root executes` otherwise). **Executors** follow: the root first (`●` while it is running, with its active model and current action) and then the lanes as before, specialists before workers. **Routing** appears only while a routed choice is live: the router's choice for the root (`<tier> via model-router → <model> for root`) and each running worker's pinned profile (`profile <id> → <model> for <label>`); nothing is credited to the router that it did not choose.

## Decision graph

The pane left of the conversation is System One's live dashboard: it shows what the loop needed, what it did, where it is and what comes next, composed from canonical state on every frame — the operator projection and its **stage log**, the Jev evaluation ledger, the router's foreground snapshot, lane records, the task's steps and the goal's requirements, verification obligations, the cycle's receipts, the lane's background tools and the questions asked. It is a projection, not a second state machine. Its running clocks tick on the lane's one-second ticker while the graph carries one; the only timer the graph owns is the animator's single 50 ms interval, which exists only while something moves (a carrier in flight, an unsettled spring) and is cleared when everything rests. The title's meta names the current stage and, after a repair, its loop (`build · loop 2`); with no stage it is blank (idle says nothing) or reads `delivered`.

The stage log derives one of ten stages from each published projection — `understand`, `plan`, `build`, `dispatch` (a non-root actor executing), `observe` (System One reviewing evidence), `verify`, `clarify` (a question to you), `repair` (a repair-class reason code or a block), `deliver`, `done` — and records every transition with its time, so a stage that runs twice keeps the accumulated time of its closed visits, while the ticking clock is only the current visit and starts again when that stage is entered. Entering `repair` increments the loop number. An idle session is not a stage: with no objective and no turn running, the log opens nothing, the graph reads "No task yet" and no clock runs; a turn without a goal is recorded as one `build` pass by the root, closed when the turn ends; a paused, limited or cancelled objective is idle the same way. Rows the placeholder projection wrote before this rule (`understand` with `no_objective`) stay in the ledger and are left out when it is read. Transitions are written to the agent directory's decision ledger (`state/decision-ledger.sqlite`, keyed by session id and working directory, append-only: rows settle, they are never deleted), Closed visits keep their durations across a restart. An open visit does not: the next read restarts that clock, so time the process was down is not counted as work. Sessions opened in the same directory never share a row. Every Jev evaluation the session runs — the recording engine, the steering plane's checkpoints and System One's stage validations — starts and settles in the same ledger with its kind, consequence, model, outcome, verdict and bounded reasons.

Three views, switched by the one pill in the pane's title (it names the current view and steps List, Diagram, Lanes on click, at a fixed width so it never moves under the pointer) or `Alt+L`, and persisted (`workbench.graphView`, `diagram` by default):

- **List**: only the stages that occurred, in the order they were first entered. A closed stage shows its accumulated time and pass count. The current stage shows this visit's clock, which starts over when the stage is entered again, and names the loop (`build · loop 2`, `← now`); then the participants with their models, the routed choices, the evidence and check counts, the judge's last verdict and the `next →` action. A click on a stage (or on its node in the Diagram: the exact node under the pointer, not its row) opens its detail — the note, the reason code, the operator events recorded while the stage was open (at most six), and the evaluation in flight — and a second click closes it.
- **Lanes**: a live sequence diagram of the flow trace. The lifeline header stays pinned at the top of the pane while the arrows scroll beneath it (a pane too short for its header shows the header only). Lifelines run down the pane: you, System One, root and each worker by name (workers the width cannot hold fold into one `+N more` lifeline, least recently active first). A hand-over is an arrow between two lifelines, running spans are activation bars on a lifeline, and a settled System One judgment carries its result and a short ledger handle after the label (`verify (stall) #a1b2`). State survives without color: a settled edge is solid (`─`), an in-flight one dashed (`┄`), a claimed one (a delegation whose worker lane is still waiting) dotted (`·`), and an outcome is a label mark (`✗` failed, `!` needs review, `×` cancelled). Layout is cell-based and orthogonal, so it holds under wide ambiguous glyph width (`PI_AMBIGUOUS_WIDTH=wide`) at 48, 80 and 120 columns.
- **Motion**: Lanes draws one carrier glyph riding an arrow while it is in flight and for 600 ms after it settles; an arrow open for more than four seconds falls back to its static dashed form with the carrier stepping once per second on the work area's existing one-second clock. The Diagram's only motion is its focus bar (below). Motion is bounded: a single 50 ms timer exists only while something moves, each frame renews a short lease while a spring is unsettled, and the timer is cleared when everything rests. `PI_REDUCE_MOTION=1` draws no carriers and the focus bar jumps.
- **Diagram**: a drawing composed per task, never a fixed skeleton, built the way the handwired library builds interfaces: the model becomes one declarative tree of boxes, one pure layout function (a Clay-style row/column engine with fixed, fit and grow sizing, integer terminal cells, water-fill growth) places every box, and the placed boxes are painted onto a cell canvas whose line drawing merges junctions into tees and crossings. Cards: `YOU` (once a question was asked), `SYSTEM ONE` with what the decider is doing and its last verdict, the plan and loop (a card titled `loop N` or `↺ loop N` after a repair, one line per stage that occurred with this visit's clock on the current one), one card per participant (the root on its active model, each specialist and worker with its route, a capability being synthesized, a background tool), the `EVIDENCE` and `CHECKS` cards, and the goal's yes/no outcome with the repair loop and `next →`. Siblings sit side by side when the width holds them and stack when it does not, always joined by orthogonal edges with a bus; the edge into the current card takes the accent tone. Clicks are answered per node from the canvas's hit map, and only a node whose stage has detail is clickable. Motion is two springs (the top and bottom of a focus bar on the left edge) that slide and stretch the bar from the node the loop left to the one it entered; all motion state is one spring table owned by the pane, cleared when the objective changes or the pane was hidden.

`Alt+G` or the `▾` at the start of the pane's title hides the pane (the conversation header then offers **Show graph**) (`workbench.graph`); the graph folds by itself, keeping the setting, when the conversation zone is narrower than 80 columns or cannot give the graph 48 columns beside a 40-column conversation. With the mouse captured the wheel scrolls the pane (it re-centres on the current step only when that step changes, so your scroll holds; `Alt+F` or **Follow current** re-centres it at once), and dragging the rule between the graph and the conversation resizes it (25%–50% of the zone, `workbench.graphFraction`; a drag that returns to its origin restores the previous width and nothing persists until release).

## Operator POV bar

One row on the status band's lane, directly above the editor's top rule, is the only normal-mode operator status surface. Every value is a live read of canonical state on each render — the session's operator projection, the router's foreground route snapshot, the semantic plane's observed health, the session cost summary, the self-compaction view and the session's events — never a literal. If a fact can be drawn it is drawn, and a label appears only where the value would not say what it is on its own:

```text
● Ready for operator instructions                                  S1 ●   CI ✓   42 tok/s   $0.083   ◷ 4:32   [###=====....+....!..|] 11.6%
```

- **Phase** (left): `WORKING` / `NEEDS INPUT` / `BLOCKED` / `DONE` in their tone and the current action; while the session is idle a dot and the sentence, because `READY` would only repeat it. **next**, **block** and **proof** appear, with a quiet label, only when there is one.
- **⇢ route**: shown only when something other than the session's own choice picked the model (`manual:<model>`, `<tier> via model-router`, `escalated→<model> via model-router`); the default (direct) is silence. The model itself is on the status line.
- **peer findings**: `N peer findings` on the warning tone, only when there are some.
- **System One**: named in words and only when it is doing or needing something: `◆ System One judging` while an evaluation runs, `System One degraded · <reason>` when the last one failed, `System One · N uncertain` while uncertain judgments are open. A healthy or idle System One says nothing.
- **CI**: the last continuous-integration run of the branch's pushed commit (the verdict the pre-push watcher records in `<git-common-dir>/pi-ci/<branch>.json`), shown only when it needs attention: `CI running` or `CI failed`. A passing or unknown run is not drawn. A watcher that died and left its record `pending` is detected (its recorded pid is gone, or an old record without one outlived any CI run) and the record is corrected from GitHub in the background through `scripts/ci-status.mjs reconcile <branch>`, so the bar never says `running` for a run that finished.
- **tok/s**: output tokens per second of the latest run, over the time assistant messages were streaming (tool time is not generation), updated as each message ends.
- **$**: the session's canonical current cost, with `(sub $…)` for spawned cost when present.
- **◷ m:ss**: the time left on the provider's prompt cache for the last request, ticking each second, then `◷ cold`; shown only for providers with a published cache lifetime (Anthropic's 5 minutes, or one hour with long retention), never guessed.
- **gauge**: the context window as a 20-cell bar (cached `#`, used `=`, free `.`) and its percentage. Marks show where compaction acts: with self-compaction on, notice `+`, warning `!` and forced `|`; otherwise the one automatic-compaction trigger the session is configured with, as `|`.

The row is two blocks: the phase text on the left and the facts anchored to the right edge, so those columns never move while the left text changes length. The left text keeps at least forty cells before facts drop, in a fixed order (CI, tok/s, cache, gauge, proof, peer findings, block, next); S1, cost and a non-direct route are never dropped.

The conversation viewport never emits the OSC 133 prompt-zone marks that the inline transcript components carry: a terminal may treat one as "a prompt starts here" and move the cursor to column 0, which corrupted framed rows in Herdr, and the alternate screen has no scrollback for those marks to navigate.

## Reading and copying

The workbench owns the mouse by default (`workbench.mouse: "on"`) and provides the two gestures a terminal would otherwise own: **drag inside the conversation to select, and the selection is copied when you release**; **right click pastes the system clipboard's text into the editor**. The wheel scrolls the surface under the pointer (conversation, Decision graph, inspector or Execution), header chips click, a click on the divider collapses or expands the work area, a drag on that divider, on the inspector/execution rule or on the graph/conversation rule resizes the panes, a click on a stage in the Decision graph opens its detail, and the title chips **Hide**, **Show plan**, **Maximize** and **Restore**, the graph title's view pill and its `▾` chevron, and the header's **Stacked** change the layout. `Alt+M` hands the mouse to the terminal instead (native selection and paste, no wheel scrolling in the workbench); the choice persists, the hint row reports the owner, and the change applies on the live screen. Most emulators also offer native selection while the workbench owns the mouse when Shift is held.

- `Alt+PageUp` / `Alt+PageDown`: scroll conversation without changing editor history. `Ctrl+End` or **Latest ↓** resumes following.
- `Ctrl+PageUp` / `Ctrl+PageDown`: page the Execution pane through the cycle's previews (`workbench.previews`, 24 by default, newest last); paging to the last page follows new evidence again. The complete record of every action stays in the transcript (`Ctrl+T`).
- Scrolling upward pauses following; the conversation header then reads *Reading* and offers **Latest ↓**.
- Wheel targets: inspector, execution or conversation under the pointer; title rows and gutters are not scroll targets, and an overflowing surface shows its visible row range in its title row. A plain click only focuses the pane; the selection starts when the pointer moves, and only then does the displayed text freeze while the model continues working. `Ctrl+X` copies the current selection again; tree-selector copying retains precedence.
- The conversation anchors to the bottom: the latest row sits directly above the status band, and a transcript shorter than the area leaves its empty rows above, never below.
- Reading position anchors to the entry under the top row. When live-history trimming removes that entry, the conversation resumes following instead of jumping to the oldest retained rows.
- A run whose own test check failed ends with its answer plus a warning line (`Verification remains unresolved …`); the inspector shows a **Checks** block listing every failing verification by command and directory. Later answers are ordinary answers; the obligations stay listed and keep `goal complete` from succeeding until the same check passes or you resolve them: `/verify` lists them, `/verify show <id>` details one, `/verify dismiss <id|all> [note]` resolves by your authority (recorded in the conversation; never counted as a passing test).
- `Alt+C` copies user/assistant prose and answered `ask_question` interactions from the current session branch, including history outside the visible window. Routine tool output is excluded. Copies above 10 MiB are refused explicitly; use `/export` instead.
- `Alt+O`: collapse or expand the work area; `Alt+I`: hide or show the inspector; `Alt+X`: maximize or restore Execution; `Alt+=` / `Alt+-`: resize the work area; `Alt+G`: hide or show the Decision graph; `Alt+L`: cycle its view through List, Diagram and Lanes (one lane each for you, System One, root and workers); `Alt+F`: re-centre the graph on the current step; `Alt+P`: stacked or columns layout. With the mouse captured: the chips on the pane titles; drag the divider, the pane rules and the column gutter to resize. `Ctrl+T`: open the complete action transcript, including images and full results.
- Questions from the `ask_question` tool and System One clarifications open in the editor slot, under both columns, never over the graph or the work area. Up to three options ride one chip row with the active option's description beneath; more options, or a row the width cannot hold, become a numbered list. While a question is open the POV bar reads `NEEDS INPUT` with `CONTROL USER`, the Decider row says `waiting for you`, and the graph lights `YOU` with a waiting clock.

New shortcuts are configurable through the existing keybinding manager: `app.conversation.pageUp`, `app.conversation.pageDown`, `app.conversation.latest`, `app.conversation.copy`, `app.execution.toggle`, `app.inspector.toggle`, `app.execution.maximize`, `app.execution.pageUp`, `app.execution.pageDown`, `app.workbench.grow`, `app.workbench.shrink`, `app.workbench.layout`, `app.graph.toggle`, `app.graph.view`, `app.graph.follow` (`Alt+F`: re-centres the pane on the current step), and `app.mouse.toggle`. Editor shortcuts and active modal navigation retain their existing owners.

Terminal-native selection cannot notify the application to pause; the application-owned drag selection (mouse captured) does pause. Clipboard transport uses the existing platform clipboard/OSC 52 adapter; remote terminal support varies.

## Talking while it works

- Enter while the model is working queues the text as **steering**: it is delivered at the next model turn, after the running tool batch completes (`steeringMode: "all"` by default, so every queued steer goes together; `"one-at-a-time"` delivers one per turn and the live row says so). A `>>` prefix (or `Alt+Enter` where the terminal passes it; the hint row shows `>>` on Windows Terminal, which swallows the key) queues a **follow-up**, delivered after this run ends.
- The live row states the boundary: `Queued 1 · 1 steering → next model turn · enter send now · alt+up edit`.
- **Enter on an empty editor** while a message is queued interrupts the running turn and sends the queued steering and follow-up messages (including any queued during compaction) as one prompt — steering first, then follow-ups, images included. Queued extension commands are not messages and stay queued; the live row lists them separately and offers `enter send now` only when a message would go. The aborted turn's message reads `Operation aborted (send now)` in the session log, so a transcript can tell it from Escape. If the submission itself fails, the text returns to the editor and the failure is shown.
- `Escape` still interrupts and restores the queued text to the editor without sending it; `Alt+Up` recalls queued text for editing.
- During compaction the queue waits for compaction to end; send-now says so instead of interrupting it.

## File effects and limits

Edit diffs, written content, command results and failures appear above conversation. Routine reads stay in the action transcript. Explicit user shell commands remain visible in the upper band.

After foreground `bash` or `python` tools finish, a read-only Git observation can reveal silent file effects. It is an event-triggered workspace comparison, not a watcher, completion detector, attribution mechanism, or proof of a clean worktree. Unchanged pre-existing changes are excluded when a baseline is available. If execution overlaps the initial snapshot, the UI says that displayed changes may predate the task. Current patches may include prior or concurrent edits.

Observations are bounded to 128 dirty paths, 32 diff paths, 256 KiB per Git response, two seconds per Git command, and 64 KiB per small-file read. Larger files use metadata. Ignored files and changes outside the current working directory are not observed. Non-Git directories and budget failures produce a notice instead of a clean-workspace claim. File effects arriving after completion still update the folded receipt.

Conversation rendering visits visible entries lazily, retains at most 2 MiB of derived row-cache text, and uses existing terminal line-diff rendering. Frame cost is bounded by the visible rows, not by history: rows that already fit their zone skip the grapheme scan, so a 224×50 frame stays under a millisecond with 2,000 transcript entries where the previous full-transcript layout needed about sixteen. Execution retains up to `workbench.previews` bounded previews per cycle (24 by default, 4..200), shows them in order with the cycle's action and file-effect counts in its title row, and follows the newest rows until the operator scrolls up; a new preview follows again. No decorative animation timer or session-history scan runs per frame. Large individual visible messages still incur their renderer's normal cost.
